# 重要通知中心 · Notice Hub

把**企业微信**和 **Outlook 邮件**里的【重要通知】统一归档到一个页面，支持全文搜索、多维度筛选和导出。

- 零第三方依赖：后端只用 Python 3.12 标准库，前端是单个 HTML 文件
- 单文件 SQLite 存储，重建容器不丢数据
- 手动导入优先，已预留自动同步接口（接采集器不用改库和前端）

### 关于企微和 Outlook 自动抓取

这里有个**必须提前知道的限制**：

- **企微群机器人 Webhook 只能发不能收**，自建应用也**读不到群历史消息**。
  想读群消息只能用官方「会话内容存档」，需要企业认证 + 付费 + 管理员审批。
- **Outlook** 要自动拉取，需要 Azure AD 注册应用并授予 `Mail.Read`（或开 IMAP + 应用密码）。

所以企微侧最现实的自动方案是：**群内「转发到邮箱」→ 服务器 IMAP 拉取 → 调入库接口**。
这和你现有的 `pa-wecom-forwarder` 是同一套模式，邮箱凭据也已经在用。

系统已经把这条路铺好了（见下文「五、接自动同步」）。

## 二、部署

目标环境：Ubuntu + Docker。项目目录建议 `/data/notice-hub`。

```bash
cd /data/notice-hub
./deploy.sh
```

`deploy.sh` 做的事：环境检查 → 生成 `.env` → 备份旧数据库 → `docker compose up -d --build` → 健康检查。

部署完访问 `http://<服务器IP>:8091`。

**初始账号：`admin` / `admin`**（首次启动 `users` 表为空时自动种入）。

> ⚠️ `admin/admin` 是弱密码，登录后页面顶部会一直挂橙色提醒条。
> **请立刻在右上角账号 → 修改我的密码里改掉**，改完提醒条自动消失。
> 系统不存明文密码（PBKDF2-SHA256 + 每账号独立盐），改密后其他设备上的登录会立即失效。

如果这个实例是别人帮你搭的、你也不知道密码，可以在服务器上直接重置：

```bash
ssh <服务器> "docker exec -it notice-hub python /app/server.py reset-admin --password 你的新密码"
```
这条命令会重置第一个管理员账号的密码并确保它处于启用状态，**不需要清库，通知数据不受影响**。

## 三、账号与权限

登录页支持多账号。角色只有两种，够用且不容易配错：

| 角色 | 能做什么 |
|------|----------|
| **管理员** | 浏览、搜索、导出；新增/编辑/删除通知；批量导入；管理分类；**管理账号**；载入/清除示例数据 |
| **查看** | 只能浏览、搜索、看详情、导出。所有写操作在**服务端**返回 403，不只是前端藏按钮 |

### 3.1 给同事开通账号

右上角 **更多 → 账号管理**（仅管理员可见）：

1. 在「新增账号」区填账号、密码，角色选 **查看**，可填姓名备注
2. 点「创建账号」，把账号密码发给同事即可

面板里还能做这些事：

| 操作 | 说明 |
|------|------|
| 改角色 | 表格里直接下拉切换，立即生效 |
| 停用 / 启用 | 停用后该账号立即无法登录，已归档数据不受影响 |
| 重置密码 | 弹窗输入新密码即可，无需知道原密码 |
| 删除 | 删除后立即无法登录 |

**几条防呆保护**（由服务端强制，不是只在前端拦）：

- 不能删除自己的账号
- 不能把自己降级为查看账号
- 不能停用自己的账号
- 至少要保留一个启用的管理员

### 3.2 同事自己改密码

点右上角自己的名字（或 更多 → 修改我的密码），输入原密码和新密码即可。

改完密码后，**该账号在其他设备上的登录会立即失效**，需要重新登录。实现方式是把密码哈希混进会话签名，因此不需要维护会话表。

### 3.3 账号密码是怎么存的

- PBKDF2-HMAC-SHA256，18 万轮迭代，**每个账号独立随机盐**
- 数据库里没有明文；接口响应里也不会带 `pwd_hash` / `pwd_salt`
- 登录失败时「账号不存在」与「密码错误」返回**同一句提示**，不泄露账号是否存在
- 密码低于 8 位或命中常见弱密码字典（admin / 123456 / password 等）会被标记为弱密码，登录后顶栏持续提醒

### 3.4 审计日志

所有登录、改密、账号增删改、通知增删、批量导入都会写入 `audit_log` 表。管理员可通过 `GET /api/audit` 查看最近 200 条（含时间与来源 IP）。

### 3.5 登录状态怎么保持（含「记住账号」）

**会话默认 30 天**，正常用不会反复要求登录。登录页有「记住账号」勾选项：勾上后账号名会存在本机，下次自动回填；**密码不落网页，交给浏览器自己的密码管理器保存**（Chrome/Edge 弹的「保存密码」，由系统钥匙串加密）。

> 为什么不在网页里存密码：网页里存只能明文放 localStorage，任何人拿到那台电脑都能读出来。交给浏览器密码管理器是同等便利度下更安全的做法。

登录页刻意使用**浏览器原生表单提交**（不是 ajax）。原因：只有原生提交，Chrome/Edge/1Password 这类密码管理器才会弹「要保存密码吗」。用 ajax 提交时浏览器基本不会提示。

**认证有两条通道**：

| 通道 | 说明 |
|------|------|
| 会话 Cookie（`HttpOnly`） | 主通道，浏览器正常时走这条 |
| `X-Session-Token` 请求头 | 兜底通道。令牌存在本机 localStorage |

为什么需要第二条：某些浏览器上下文**不会保存 Cookie** —— 内嵌 webview、IDE/预览面板、被代理剥离 Cookie 的环境。这种情况下只靠 Cookie 会出现「**登录成功，但下一个请求立刻提示会话已过期**」并且无限循环。有了兜底通道，这类环境也能正常用。

两条通道共用同一个签名令牌，所以改密码 / 停用 / 删号依然是**立即全局失效**。

### 手动操作

```bash
cd /data/notice-hub
docker compose up -d --build     # 构建并启动（改代码后必须带 --build）
docker compose ps                # 看状态
docker logs -f notice-hub        # 看日志
docker compose down              # 停止（数据保留在 ./data）
```

### 端口绑定（只开内网）

默认**只绑内网网卡**，公网接口完全不可达：

```yaml
ports:
  - "10.0.0.10:8091:8091"   # 换机器时改这个 IP
```

改成 `"8091:8091"` 会监听所有网卡（含公网）—— 本项目的页面会在免登录视图下暴露内网系统地址，
**不建议**这么做。换端口就改冒号右边那对数字。

> ⚠️ 绑内网网卡后，**服务器上 `curl 127.0.0.1:8091` 是不通的**（那走的是回环，不在绑定范围内）。
> 要自测请用内网地址：`curl http://10.0.0.10:8091/api/health`，或从容器内自检：
> `docker exec notice-hub python -c "import urllib.request;print(urllib.request.urlopen('http://127.0.0.1:8091/api/health').read())"`
> `deploy.sh` 的健康检查已经改成走容器内自检，不受绑定影响。

## 四、内网导航门户（默认首页）

打开 `http://<服务器IP>:8091` 直接就是**内网导航页，不需要登录**。散在各处的内网系统按业务域分组，点卡片在新标签打开。

### 4.1 在线状态探测

每张卡片右上角有个状态点：绿=在线、红=探测失败、灰=未探测。后端每 60 秒批量探一轮（`NAV_PROBE_INTERVAL`），也可以点右上角「重新探测」立刻触发。

探测用 **TCP 连通性**而不是 HTTP 请求 —— 对 FTP、HTTPS、非 HTTP 服务一样有效，也不会因为 401/302 这类状态码被误判成离线。

> ⚠️ 默认**只探测内网地址**（设 `NAV_PROBE_ALLOW_PUBLIC=1` 可放开）。这是防止本服务被当成对外端口扫描器用。所以公网目标的状态会显示「未探测」而不是「失败」。

搜索框按名称、描述、标签、地址过滤，按 `/` 键可直接聚焦。

### 4.2 可见性（免登录 / 需登录 / 仅管理员）

每个导航项有独立的可见性：

| 取值 | 谁能看到 |
|------|----------|
| **免登录可见**（默认） | 任何能访问本页的内网用户 |
| **需登录可见** | 登录后的账号（含查看角色） |
| **仅管理员可见** | 只有管理员 |

> ⚠️ 导航页免登录，意味着**内网 IP 和端口对任何能访问本页的人可见**。这是当前选定的模式。想收紧某个系统，把它的可见性改掉即可，**不用改代码**。

### 4.3 维护导航项

右上角「管理导航」（需管理员登录）可以：

- 新增 / 编辑 / 删除导航项，上下箭头调顺序
- 新增 / 改名 / 排序 / 删除分组（**删除分组会连带删除该分组下的导航项**）
- 改可见性、颜色、标签、图标文字、是否参与探测、是否标记常用

「图标文字」留空时自动取名称首字。改动立即生效，导航数据存在数据库里，重启容器不丢。

### 4.4 进入通知中心

**「重要通知中心」这张卡片本身就是入口** —— 点它直接切到通知中心（同一标签页），未登录会先要求登录；通知中心左上角「返回导航」回来。用的是同一套账号（见「三、账号与权限」）。

实现上区分了两种情况：

| 卡片地址 | 打开方式 |
|----------|----------|
| **与本页同源**（如 `http://<本机>:8091/#/notices`） | 站内路由，**同标签页**切换 |
| 其它地址（含同主机的其它端口） | `target="_blank"`，**新标签页**打开 |

所以想把某个系统做成站内页面，把它的地址填成本站同源地址 + hash 即可；中键 / Ctrl+点击仍然走浏览器默认的新开标签。

> 导航页右上角不再单独放「通知中心」按钮 —— 入口只保留卡片一处，避免点卡片回到导航页的绕圈。

> 换服务器时改导航地址：种子数据里的主机名取自环境变量 `NAV_HOST`，改完删掉 `nav_groups` 表内容重新初始化即可；也可以直接在「管理导航」里逐条改。

## 五、日常使用

### 5.1 导入通知

点右上角 **导入**，三个标签页：

**① 粘贴文本** —— 从企微聊天记录或邮件正文直接粘。

每条通知之间用单独一行 `---` 分隔。每条开头可以写 `键: 值` 头部，**空行之后的内容全部当作正文**：

```
标题: 【重要】9月18日广州机房核心交换机版本升级
来源: 企微
群名称: 运维值班群
发布人: Alex Chen
发布时间: 2026-09-15 10:30
分类: 网络变更
级别: 紧急
标签: 割接, 机房

计划于 9 月 18 日 00:00-04:00 对核心交换机做版本升级，期间业务中断不超过 90 秒。
---
标题: FortiClient EMS 7.4 强制升级
来源: Outlook
发布时间: 2026-09-12 09:05
分类: 安全通告
级别: 重要

请在 9 月 30 日前完成客户端升级。
```

可用的键（中英文都认）：`标题/title`、`正文/content`、`来源/source`、`群名称`、`发布人`、`发件人`、`时间/发布时间`、`分类`、`级别`、`标签`、`附件`、`置顶`、`外部ID`。

不写头部也能用，系统会把**第一行当标题**、其余当正文。

**② 上传文件** —— 支持多选：

| 格式 | 说明 |
|------|------|
| `.eml` | Outlook 里选中邮件拖到桌面即可得到，自动解析标题/发件人/时间/正文/附件 |
| `.xlsx` | 首行作为表头，列名按上面的键匹配 |
| `.csv` | 自动识别 UTF-8 / GB18030 编码和分隔符 |
| `.json` | 对象数组，键名同上 |
| `.txt` / `.md` | 按「粘贴文本」的格式解析 |

**③ 自动同步** —— 显示入库接口地址和同步令牌（见第五节）。

### 5.2 查询

- **搜索框**：多个关键词用空格分隔，**全部命中才算**（AND）。标题、正文、标签、发布人、发件人、群名、分类都参与匹配，结果里关键词会高亮。
- **左侧筛选**：来源（企微/Outlook/手工/其它）、重要级别、分类、时间范围（今天/7天/30天/90天/自定义），可多选叠加。
- **快捷键**：`/` 聚焦搜索框，`Esc` 关闭弹窗。
- **导出**：工具栏「导出」按钮导出**当前筛选结果**为 CSV；「更多」菜单里还能导 JSON。

### 5.3 去重规则

同一条通知反复导入不会产生重复记录。判定依据是 `ext_id`：

- 邮件：用 `Message-ID` 生成
- 采集器上报：用采集器给的 `ext_id`
- 手工录入：按「来源 + 标题 + 发布时间 + 发件人」算哈希

## 六、数据与备份

数据库是单个文件：`/data/notice-hub/data/notices.db`（含 `-wal` / `-shm` 两个附属文件）。

```bash
# 手工备份（三件套一起拷，保证自洽）
cd /data/notice-hub
docker exec notice-hub python -c "import sqlite3;c=sqlite3.connect('/app/data/notices.db');c.execute('PRAGMA wal_checkpoint(TRUNCATE)');c.close()"
cp data/notices.db* /some/backup/path/
```

`deploy.sh` 每次执行都会自动备份到 `data/backups/`，保留最近 20 份。但那只在**部署时**触发，平时还需要单独做定时备份。

> ⚠️ 教训来自你 CSE 那套系统：SQLite 靠 `docker restart` 强杀容易让 WAL 落盘失败导致库损坏。
> 本项目也据此处理：容器收到 SIGTERM 走正常退出流程，`deploy.sh` 用 `docker compose up -d` 而不是反复 `restart`。

## 七、接自动同步（后续）

系统已经留好了入口，**不需要改数据库和前端**：

```
POST  /api/ingest
Header:  X-Sync-Token: <令牌>
Body:    {"items": [ {...}, {...} ]}
```

令牌位置：页面右上角 **导入 → 自动同步** 标签页（或服务器 `.env` 里的 `SYNC_TOKEN`，留空则按会话密钥派生）。

字段同导入用的键：`ext_id`、`source`、`source_name`、`sender`、`title`、`content`、`publisher`、`published_at`、`category`、`level`、`tags`。

按 `ext_id` 幂等：重复上报只更新、不新增，所以采集器可以放心重跑。

### 采集器怎么写

推荐照 `pa-wecom-forwarder` 的现成套路（Python 标准库 `imaplib` + `email` 即可，不用装依赖）：

1. 企微群里配「转发到邮箱」，Outlook 里配规则自动转发到同一个**专用邮箱**
2. 服务器上一个定时脚本 IMAP 拉未读邮件 → 解析 → POST 到 `/api/ingest` → 成功后标记已读
3. `sync_sources` 表已经预留，可以通过 `GET/POST /api/sync/sources` 管理采集源配置

**关键坑**（`pa-wecom-forwarder` 已经踩过，可直接复用结论）：

- 用**专用邮箱**，不要和个人邮箱混用 —— 脚本靠「未读」判断新邮件，别人用手机点开就会漏
- 发件人过滤放在**本地代码**里做，不依赖邮箱搜索索引（APPEND 的邮件很多邮箱不建索引）
- 先查垃圾箱，外部系统通知邮件极易被判垃圾

## 八、故障排查

| 现象 | 排查 |
|------|------|
| 打不开页面 | `docker compose ps` 看容器状态；`ss -tuln \| grep 8091` 看端口；`docker logs notice-hub` |
| **登录成功却一直提示「会话已过期」** | 这是浏览器没保存 Cookie 的典型症状。已内置令牌兜底通道，正常情况下不该再出现。若仍出现，看日志定位：`docker logs notice-hub 2>&1 \| grep 401` 会打印每次 401 的令牌来源（`cookie=有/无`、`X-Session-Token=有效/无效`）。另外确认浏览器没禁用本站的 Cookie 与 localStorage |
| 忘记管理员密码 | `docker exec notice-hub python /app/server.py reset-admin --password 新密码` |
| 同事说登录不了 | 账号管理里看是不是被停用了；或直接给他重置密码 |
| 同事说看不到「导入」按钮 | 正常行为 —— 查看角色没有写权限 |
| 浏览器不弹「保存密码」 | 确认用的是正常浏览器窗口（不是内嵌预览面板）；登录页需为原生表单提交（本页已是） |
| 导入说没解析到通知 | 检查每条之间是否用单独一行 `---` 分隔；CSV/XLSX 首行表头名是否用了下面的键名 |
| 时间差 8 小时 | 检查 `.env` 的 `APP_TZ_OFFSET_HOURS`（默认 8） |
| 数据没了 | 看 `data/notices.db` 是否还在；`data/backups/` 有历史备份 |
| 忘记同步令牌 | 页面「导入 → 自动同步」里能直接看到并复制 |
| 导航页打不开 / 空白 | 打开 `http://<IP>:8091/` 应直接显示导航；若跳登录页说明静态资源旧了，强刷 `Ctrl+F5` |
| 服务器上 `curl 127.0.0.1:8091` 不通 | 正常 —— 端口只绑了内网网卡。改用内网 IP 或容器内自检 |
| 导航卡片全是灰色「未探测」 | 目标不是内网地址（默认不探公网），或探测线程未启动，看 `docker logs notice-hub \| grep 导航` |

## 十一、安全注意

- **`admin/admin` 是弱密码**，登录后顶栏会一直提醒，请立刻改掉
- 页面按「只在内网访问」部署，如需暴露到公网，建议前面加 nginx 做 HTTPS + IP 白名单
- 账号密码用 PBKDF2 加盐哈希存储，不存在明文；审计日志会记录登录来源 IP
- `.env` 与同步令牌不要提交到代码仓库（`.gitignore` 已排除）
- 同步令牌等同于写入权限，泄露后任何人都能往库里塞数据
